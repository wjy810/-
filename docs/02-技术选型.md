## 1. 选型原则

1. **为需求服务**：每个依赖都要对应需求文档中的具体能力或非功能指标，不为“新”而换。
2. **保留有效资产**：现有后端 343 项测试全部通过、业务规则沉淀充分，不推倒重写；前端按“设计系统先行、页面逐个迁移”演进。
3. **可访问性与健壮性内建**：优先选用已经解决焦点管理、键盘交互、ARIA 的成熟原语，而不是继续手写。
4. **总包体积可控**：公开首页首屏 JS（gzip）≤ 180KB；每新增一个运行时依赖都要说明体积代价。
5. **单一做法**：同一类问题只保留一种方案（一种状态管理、一种请求缓存、一种弹层实现）。

## 2. 旧选型的问题

| # | 问题 | 现状证据 | 影响 |
| --- | --- | --- | --- |
| 1 | 首页为一个装饰性 3D 场景引入 Three.js | `three@0.185` + `EvidenceStudio.vue` + `evidenceScene.ts`，独立 chunk 约 535KB（gzip 135KB），还需要三档画质、WebGL 丢失回退、闲置停止等大量防护代码 | 首页变重、维护成本高、移动端直接降级为静态图，投入产出比低 |
| 2 | 没有状态管理与服务端缓存方案 | 每个页面在 `onMounted` 里手动请求、手动维护 `loading / error`，模块级 `ref` 充当全局状态 | 页面来回切换每次都白屏重载；同一数据多处请求；错误处理风格不一 |
| 3 | 基础组件全部手写，且可访问性靠逐个补丁 | `AppSelect.vue` 631 行、`AppDatePicker.vue` 468 行、`AppModal.vue` 247 行，各自实现焦点、键盘、定位 | 缺陷面大；新组件（下拉菜单、气泡、提示）没有统一底座 |
| 4 | 样式体系失控 | `landing.css` 2214 行、`career-library.css` 2186 行、全局 `style.css` 1028 行；大量硬编码颜色（`#eef1f5` 等）；`public/legacy-release.css` 作为历史补丁仍在加载链路 | 无法做主题（深色模式）；改一个颜色要全仓搜索；页面风格不一致 |
| 5 | 超大单文件组件 | `AiResumeWorkbenchPage.vue` 2796 行（脚本 1749 行），引导卡片与模块编辑两套几乎相同的表单模板重复约 140 行 | 修改风险高，历史上出现过模板切换覆盖未保存内容等缺陷 |
| 6 | 工具链版本与运行环境耦合过紧 | `engines` 强制 Node `>=24.15 <25`，启动脚本拒绝其他版本 | 开发者和 CI 环境稍有差异就无法启动 |
| 7 | 后端缺少结构约束与可观测性 | 模块间依赖无自动检查；无请求 ID；日志为纯文本 | 模块边界随时间腐化；线上问题难以关联到具体请求 |
| 8 | 运行时停留在 Java 17 | 镜像 `eclipse-temurin:17-jre` | 无法使用虚拟线程；AI 流式与外部 HTTP 调用阻塞平台线程 |

## 4. 前端详细选型

### 4.1 框架：继续使用 Vue 3

| 方案 | 结论 | 理由 |
| --- | --- | --- |
| **Vue 3.5 + TS**（现状） | ✅ 采用 | 4.7 万行代码与 84 个组件测试基于 Vue；团队熟悉；组合式 API 足以支撑工作台类复杂交互。 |
| React 19 + Next | ❌ | 迁移成本等于重写，收益不对等；本产品是登录后的工作台，不需要 SSR。 |
| Nuxt 4 | ❌ | 同上，SSR / SSG 只对公开首页有意义，首页可通过预渲染单独优化。 |

### 4.2 全局状态：Pinia

| 方案 | 结论 | 理由 |
| --- | --- | --- |
| **Pinia** | ✅ | Vue 官方推荐；类型推导完整；支持 DevTools 与 SSR；用于会话、偏好（主题、侧边栏）、命令面板、未读数等少量**客户端**状态。 |
| 模块级 `ref`（现状） | ❌ | 无法调试、无法在测试中重置，容易形成隐式耦合。 |

**边界**：Pinia 只存客户端状态。来自服务器的数据一律交给 TanStack Query，禁止在 Pinia 里缓存接口返回值。

### 4.3 服务端状态：TanStack Query

| 方案 | 结论 | 理由 |
| --- | --- | --- |
| **@tanstack/vue-query** | ✅ | 缓存 + 后台刷新让页面切换“秒开”（需求 8.1：已缓存数据 ≤ 100ms 呈现）；自动去重并发请求；失败重试与指数退避；变更后按 key 精确失效；窗口聚焦刷新支撑通知未读数。 |
| 手写 `onMounted + ref`（现状） | ❌ | 每页重复 loading / error 样板；切页白屏。 |
| Pinia 缓存接口数据 | ❌ | 需要自己实现过期、去重、重试，等于重写 Query。 |

**约定**：
- 查询 key 统一由各模块 `queries.ts` 中的 key 工厂生成，如 `resumeKeys.list()`、`resumeKeys.detail(id)`。
- 默认 `staleTime: 30s`、`gcTime: 5min`、GET 失败重试 2 次（4xx 不重试）。
- AI 简历工作台这类“本地编辑态复杂、需要精细保存控制”的页面，使用专用组合式函数 + 保存队列，不强行套用 Query 的 mutation。

### 4.4 交互原语：Reka UI

| 方案 | 结论 | 理由 |
| --- | --- | --- |
| **Reka UI**（原 Radix Vue） | ✅ | 无样式（不与设计系统冲突）；内建焦点锁定、键盘导航、ARIA、碰撞检测定位；覆盖 Dialog、Popover、DropdownMenu、Select、Combobox、Tooltip、Tabs、Switch、Checkbox、RadioGroup、ToggleGroup、Slider、ScrollArea；按需引入可 tree-shake。 |
| Element Plus / Naive UI / Ant Design Vue | ❌ | 自带强烈视觉风格，覆盖样式成本高，产品会“长得像后台”；体积大。 |
| 继续手写（现状） | ❌ | 见第 2 节问题 3。 |

**做法**：在 `shared/ui` 中用 Reka 原语 + 设计令牌封装 `Ui*` 组件（如 `UiDialog`、`UiSelect`），业务代码只用 `Ui*`，不直接引用 Reka，便于将来替换。

### 4.5 样式：设计令牌 + scoped CSS

| 方案 | 结论 | 理由 |
| --- | --- | --- |
| **CSS 自定义属性令牌 + SFC scoped CSS** | ✅ | 零运行时；与现有 SFC 写法一致；令牌一次定义即可支持浅色 / 深色主题和“减少动效”；可读性好，适合中文团队协作。 |
| Tailwind CSS v4 | ❌ | 与现有 scoped CSS 形成两套范式；模板中长 class 串降低复杂表单的可读性；主题能力同样依赖 CSS 变量，收益有限。 |
| CSS-in-JS | ❌ | 运行时开销，Vue 生态支持弱。 |
| UnoCSS | ❌ | 同 Tailwind 的理由。 |

**规则**：
- 颜色、字号、间距、圆角、阴影、时长、缓动只允许使用令牌（`var(--…)`），禁止硬编码色值（插画与简历模板渲染除外）。
- 令牌分两层：**基础令牌**（色板，如 `--ink-600`）与**语义令牌**（如 `--color-primary`、`--surface-raised`）。组件只引用语义令牌。
- 全局样式只包含：reset、令牌、排版基线、少量布局原语（`stack`、`cluster`、`grid-auto`）、动效关键帧。其余全部写在组件 scoped 样式中。
- 删除 `public/legacy-release.css` 与 `scripts/build-legacy-style.mjs`。

### 4.6 字体

| 方案 | 结论 | 理由 |
| --- | --- | --- |
| **Inter Variable（@fontsource-variable/inter 自托管）+ 系统中文字体** | ✅ | Inter 让英文与数字（分数、日期、额度）更精致，支持 `tabular-nums`；仅拉丁子集约 50KB（woff2）；中文使用 PingFang SC / HarmonyOS Sans SC / 微软雅黑 / Noto Sans SC，零下载。 |
| 网络加载中文 Web 字体 | ❌ | 中文字体动辄数 MB，与首页性能目标冲突。 |
| 纯系统字体（现状） | ❌ | 数字与英文在 Windows 上观感较差。 |

简历 PDF 渲染继续使用后端内置的 Noto Sans SC / Noto Serif SC，保证导出一致性。

### 4.7 动效

| 方案 | 结论 | 理由 |
| --- | --- | --- |
| **CSS 过渡 / 关键帧 + Vue `<Transition>` / `<TransitionGroup>` + View Transitions API** | ✅ | 满足页面切换、弹层、列表进出、FLIP 重排等全部场景；零依赖；可统一由令牌控制时长与缓动并响应“减少动效”。 |
| motion-v / GSAP | ❌ | 本产品动效以 UI 反馈为主，不需要时间线编排；增加约 30–60KB。 |
| Three.js 场景（现状） | ❌ | 见第 2 节问题 1。 |

### 4.8 拖拽：vue-draggable-plus

用于简历设计视图的模块排序、编辑视图的条目排序。基于 SortableJS，支持触屏和动画；约 15KB gzip，仅在工作台 chunk 中加载。保留上移 / 下移按钮作为键盘可达的替代方案。

### 4.9 插画与视觉素材

| 方案 | 结论 | 理由 |
| --- | --- | --- |
| **AI 生成透明底 3D 黏土风插画 → 压缩为 WebP** | ✅ | 风格统一、温暖，契合年轻用户；透明底可自由组合（首页主视觉由多个子元素拼合，并配合 CSS 浮动动效）；单张 20–80KB。 |
| 图库插画 | ❌ | 风格难统一、版权约束。 |
| Three.js 实时渲染 | ❌ | 见上。 |

素材源文件与生成提示词保存在 `design/illustrations/`，便于再生成。前端产物放 `frontend/src/assets/illustrations/`。

### 4.10 质量工具

| 工具 | 用途 |
| --- | --- |
| `vue-tsc` | 类型检查（CI 必过） |
| Node test runner | 纯函数逻辑测试（零依赖、启动快） |
| Vitest + Vue Test Utils + jsdom | 组件与组合式函数测试 |
| Playwright | 端到端流程与视觉截图回归 |
| `scripts/lint-critical.mjs` | 关键规则检查（新增：禁止硬编码色值、禁止业务代码直接引用 Reka） |

### 4.11 运行环境

- Node：`>=22.12`（Vite 8 要求），`.node-version` 推荐 24 LTS；启动脚本只校验下限，不再拒绝新版本。
- 包管理：npm（单一锁文件 `package-lock.json`）。

## 5. 后端详细选型

### 5.1 架构形态：模块化单体（保留）

| 方案 | 结论 | 理由 |
| --- | --- | --- |
| **模块化单体** | ✅ | 2 核 2G 单机部署目标；19 个业务模块共享事务与数据库；运维成本最低。通过 ArchUnit 守住模块边界，保留将来拆分的可能。 |
| 微服务 | ❌ | 用户规模与团队规模都不需要；分布式事务、部署和观测成本过高。 |

### 5.2 运行时：Java 21 LTS

| 方案 | 结论 | 理由 |
| --- | --- | --- |
| **Java 21 LTS** | ✅ | 虚拟线程（`spring.threads.virtual.enabled`）让 AI 流式输出、外部模型调用、SSE 等阻塞 IO 不再占用平台线程，在 2 核 2G 机器上显著提升并发能力；模式匹配、record 模式改善代码可读性；Spring Boot 3.5 完整支持。 |
| Java 17（现状） | ❌ | 无虚拟线程。 |
| Java 25 | ⏸ | 待生态（Spring Boot 4、依赖库）稳定后评估。 |

镜像改为 `eclipse-temurin:21-jre-jammy`，编译 `release 21`。虚拟线程默认在生产开启，可通过 `JOBPROOF_VIRTUAL_THREADS=false` 关闭。

### 5.3 框架与库（保留并说明）

| 组件 | 选型 | 说明 |
| --- | --- | --- |
| Web | Spring Boot 3.5 / Spring MVC | 同步模型 + 虚拟线程，比 WebFlux 更易维护 |
| 安全 | Spring Security + 自研 Cookie 会话过滤器 | 会话存数据库，支持撤销；BCrypt |
| 持久化 | Spring Data JPA（聚合写模型）+ JdbcTemplate（复杂查询 / 批量） | 规则：写路径优先 JPA 实体或带版本条件的 SQL；读路径可用 JdbcTemplate 投影；**禁止“先读版本再无条件更新”** |
| 迁移 | Flyway | 只增不改；H2 与 MySQL 双兼容 |
| 校验 | Jakarta Validation | 所有请求 DTO 必须声明约束 |
| HTTP 客户端 | Apache HttpClient 5 / OkHttp | 模型通道调用，统一超时与重试 |
| 文档 | PDFBox 3、POI 5、jsoup | 简历 PDF / DOCX 渲染与导入 |
| 对象存储 | MinIO Java SDK | 私有桶 + 服务端鉴权下载 |

### 5.4 架构约束：ArchUnit

在测试中以代码形式固化 [架构设计](03-架构设计.md) 第 5 节的分层与模块规则，例如：

- `..web..` 只能依赖本模块的 `..application..`，不能直接访问 `..infra..`；
- 模块之间只能通过对方的 `application` 公开服务访问，不能访问对方的 `infra` / `domain` 内部实现；
- `infrastructure` 不能依赖任何业务模块；
- 控制器类名以 `Controller` 结尾且只在 `web` 包中。

现有违规以“冻结清单”形式记录，新代码不得增加违规；清单只减不增。

### 5.5 可观测性

| 能力 | 方案 |
| --- | --- |
| 请求追踪 | `RequestIdFilter`：读取或生成 `X-Request-Id`，写入 MDC 与响应头，错误响应体携带 `requestId` |
| 结构化日志 | Spring Boot 内置 `logging.structured.format.console=ecs`（生产），开发保持可读文本 |
| 指标 | Actuator + Micrometer（`/actuator/health`、`/actuator/prometheus` 仅内网） |
| 慢请求 | 超过 1s 的请求记录 WARN 日志（含 Request-Id、路径、耗时） |

### 5.6 不采用的技术

| 技术 | 原因 |
| --- | --- |
| Kafka / RabbitMQ | 现有数据库 Outbox + 进程内 Worker 满足异步需求；单机部署不值得引入 |
| Elasticsearch | 搜索需求（简历标题、模板筛选）由 SQL 满足 |
| GraphQL | 前端页面与接口一一对应，REST 足够；增加缓存与权限复杂度 |
| 逆向招聘平台接口 / Cookie 抓取 | 合规风险，需求明确不做 |

## 7. 风险与应对

| 风险 | 应对 |
| --- | --- |
| 新旧前端组件并存期间风格不一 | 先完成设计系统与外壳，再按页面迁移；迁移完成后删除旧组件，CI 检查禁止引用已废弃组件 |
| TanStack Query 与旧的手动请求逻辑混用 | 新写或重构的页面统一使用 Query；工作台保存链路保持专用保存队列 |
| 虚拟线程与 `synchronized` 长持锁导致线程钉住 | 审查 AI 网关与 SSE 中的同步块；开启 `-Djdk.tracePinnedThreads=short` 于预发布环境观测；提供开关 |
| 插画生成风格漂移 | 固定提示词模板与调色板，所有素材在 `design/illustrations/prompts.md` 记录 |

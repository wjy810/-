## 1. 结论先行

一期把应用外壳、设计系统、工作台和后端健壮性做到了可用水准。二期审计发现，剩下的问题集中在三类：

1. **简历模板是演示品**：12 套模板是同一骨架的参数组合，状态全是草稿，靠演示开关显示；导出的 PDF 用另一套手绘渲染器，和预览不一致（§2）。
2. **“看起来能用”的假数据与假控件**：客户端模拟的进度和预计时间、规则编造的面试分数、带保底分的“相似方向”、永远打勾的冻结检查、写死的倒计时和训练建议、点了没反应的按钮（§3.2）。
3. **失败被伪装成“没有数据”**：约 15 个页面加载失败后显示空态或 0，用户以为自己没有记录（§3.1 X-1）。

二期的原则：**宁可少一个功能，也不展示一个假结果。**做不到真实的，就如实标注或移除。

## 2. 简历模板：诊断

### 2.1 预览与导出不一致（实测）

同一份简历（模板“校园新锐”）在工作台预览与导出 PDF 的对比：

| 项 | 屏幕预览 | 导出 PDF |
| --- | --- | --- |
| 渲染器 | `ResumeTemplatePreview.vue`（HTML/CSS） | `ResumeStructuredPdfRenderer.java`（PDFBox 逐行画字） |
| 字体 | 用户电脑上的微软雅黑 / 宋体 | 打包的 Noto Sans SC 单字重 |
| 姓名、标题、公司名 | 加粗 | 全部常规字重 |
| 断行 | 浏览器排版 | 自写按宽度截断，出现“具备 Java / 后端开发实习经验”式错误折行 |
| 页面结构 | 页头有边距，板块间距舒展 | 页头贴顶，板块挤在一起，侧栏色块拉满整页 |
| 分页 | 按“容量单位”估算 | 按自写逻辑计算，两者页数可能不同 |

### 2.2 设计层面

- 12 套模板的差异仅在：单栏或双栏比例、4 种页头之一、5 种标题样式之一、2 种颜色。没有时间轴、编号章节、满版色块、纹理装饰等任何“有个性”的版式。
- 页头在没有照片时显示“JP”字样——用户自己的简历上出现了产品标记。
- 字号偏小（正文约 8.5pt），层级弱，大面积留白不均匀。
- 所有模板 ATS 等级都是“未验证”。

### 2.3 重构方向

统一渲染引擎 + 16 套新设计模板 + 渲染服务 + 导出校验，详见 [技术选型](02-技术选型.md) 与 [架构设计](03-架构设计.md)，版式规格见 [UI/UX 设计](04-UIUX设计.md) §3。

## 6. 验收标准

1. 任一模板、任一配色下，工作台预览的页数与导出 PDF 页数一致；同一份内容，预览截图与 PDF 第一页渲染图逐像素差异 ≤ 0.5%（Chromium）。
2. 导出 PDF 的文字层包含姓名、联系方式、全部板块标题与条目标题，顺序与阅读顺序一致；字体为 CID TrueType。
3. 16 套模板在“完整内容 / 极少内容 / 超长内容 / 英文”四份示例下均无文字溢出页面、无重叠。
4. 生产配置下（演示开关关闭）模板中心与工作台都有可用模板。
5. §3 中标 ✅ 的条目全部有对应提交与测试；任何页面加载失败时显示错误与重试，而不是空态。
6. 模拟面试会话页在浅色与深色主题下所有文字对比度 ≥ 4.5:1。

# 通知偏好与邮件提醒

> 状态：第一版已上线（V76）。

## 1. 为什么要做

投递追踪、查看回执、下一步提醒、会员到期提醒上线以后，站内通知变成了求职过程里最及时的信号。但求职者不会一直开着网页：面试前一天的提醒、“合成科技打开了你的简历”只在铃铛里，往往错过。另一方面，消息多了，用户也需要能关掉自己不关心的那一类。

## 2. 产品形态

**设置 › 通知**（`/account/notifications`）按消息类型给出两个开关：

| 类型 | 何时发 | 通知中心（默认） | 邮件（默认） |
| --- | --- | --- | --- |
| 简历回执 | 对方首次打开简历、出现新的读者 | 开 | 开 |
| 日程提醒 | 笔试、面试等下一步开始前一天 | 开 | 开 |
| 会员 | 专业版到期前 7 天、到期时 | 开 | 开 |
| 求职周报 | 每周一上午：上周投递与被打开情况、本周安排（见 [06-求职周报](06-求职周报.md)） | 开 | 开 |
| 产品更新 | 新版本发布 | 开 | 关 |

账号安全、数据导出与删除、AI 任务结果的通知不能关闭，也不发邮件。

- 邮件只发到**已验证**的邮箱；没有时页面引导去“账号与安全”绑定。站点没有配置发件服务时，邮件开关整体不可用并说明原因，站内通知照常。
- 每个事件最多一封邮件（与站内通知同一个事件 ID 去重）。邮件里有“查看详情”直达对应页面（需配置 `jobproof.public-base-url`），底部说明在哪里关闭。
- 关闭“通知中心”后，这类消息不再进入铃铛和通知列表；已经收到的不受影响。
- 通知中心页头有“通知设置”入口；命令面板可搜索“通知设置”。

## 3. 实现

- `notification_preferences`：每个账号每种类型一行，没有行时用默认值。
- `notification_emails`：发件箱。新通知产生时，在同一步按偏好写入一行（`account_id + type + event_id` 唯一）；`NotificationEmailWorker` 每 15 秒扫描到期的行。
- **租约**：发送前先用条件更新把 `attempts + 1`、`next_attempt_at` 推后 5 分钟，抢到的实例才发送，多实例不会重复；发送中途崩溃，5 分钟后自动重试。
- **重试**：失败后按 1 分钟、5 分钟、30 分钟、2 小时退避，第 5 次仍失败标记为 `FAILED`，保留最后一次错误摘要。
- **转义**：标题与正文里的公司名、岗位名等用户内容在 HTML 中转义；纯文本版本同时发送。
- **发件渠道**：管理员可以在“后台 › 邮件设置”里配置 SMTP 账号并开关提醒邮件，保存后立即生效（见 [05-邮件设置](05-邮件设置.md)）。没有后台配置时按环境变量：`jobproof.notification.email.provider` = `smtp`（复用 `spring.mail` 与验证码的发件账号）/ `dev`（只记在内存并打日志，开发环境默认）/ `none`（默认，关闭邮件）。
- **数据权利**：偏好与邮件发送记录纳入账号导出（`notificationSettings`）；注销账号时删除两张表中该账号的数据，未发出的邮件随之取消。

## 4. 接口

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/api/v1/notification-preferences` | 各类型的开关、站点是否开通邮件、已验证邮箱（打码） |
| PUT | `/api/v1/notification-preferences` | `{ items: [{ type, inApp, email }] }`，只能修改上表中的五种类型 |

## 5. 下一步

- 微信服务号 / 小程序订阅消息：同一个发件箱增加一个渠道即可，偏好表增加一列。
- 每日摘要：把当天的回执合并成一封邮件，适合投递量大的用户。

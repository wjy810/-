# 运营概览

> 状态：第一版已上线（`/admin/overview`，管理员登录后的首页）。

## 1. 为什么要做

会员、兑换码和投递回执上线后，运营方需要回答几个基本问题：有多少人在用、新用户从哪一步流失、专业版转化了多少、兑换码发出去用掉了多少、AI 花了多少。以前只能直接查库。

## 2. 页面

| 区块 | 内容 |
| --- | --- |
| 指标卡 | 求职者总数（近 7 / 30 天新增）、近 7 天回访人数（近 30 天）、当前专业版人数与占比（近 30 天开通次数）、本月 AI 次数与在用人数 |
| 每日趋势 | 近 14 天的新注册、新投递、简历被打开，各一张柱状图（不同量纲不共用一根坐标轴）；只标注峰值和今天，其余数值在悬停 / 键盘聚焦的提示与“查看每日数据”表格里 |
| 转化漏斗 | 注册 → 写了简历 → 记录投递 → 简历被打开 → 开通过专业版，累计人数；每一步与上一步相比，专业版与注册人数相比 |
| 模块使用 | 简历、投递记录、专属链接、简历被打开、岗位匹配、模拟面试的累计数与近 7 天新增 |
| 兑换码 | 已生成、已兑换、仍可兑换的批次，直达兑换码管理 |

## 3. 口径

- **只统计求职者**（`role = 'SEEKER'`），管理员与运营账号不计入任何数字。
- **回访**：近 N 天内有过登录会话活动（`sessions.last_seen_at`）的人数。
- **专业版人数**：到期时间晚于现在的专业版；**开通过专业版**：有过任意一次开通记录的人数。
- **AI 次数**：本月（北京时间自然月）各账号已结算的次数之和，与“设置 › AI 用量”一致。
- 每日数据按北京时间切分日期。
- 数据实时计算，只读，不另存快照。

## 4. 接口

`GET /api/v1/admin/overview`：管理员可用，其他账号返回 403。

## 5. 下一步

- 按渠道（兑换码批次、投递渠道）拆分转化。
- 周报：每周一把上周的核心数字发到运营邮箱。
- 留存曲线：按注册周统计第 1、2、4 周的回访比例（需要按日记录活跃，`last_seen_at` 只保留最近一次）。

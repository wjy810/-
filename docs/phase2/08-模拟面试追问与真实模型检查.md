# 模拟面试真追问，与四个 AI 功能的真实模型检查

> 状态：已上线（V81）。真实模型检查于 2026-10-19 至 10-20 进行，使用开发环境的 gpt-6.1-sol 通道。

## 1. 动态追问

**改之前**：“动态追问”只是在点评里列一句“可能的追问”，面试过程中不会被问到，开关名不副实。

**现在**：

- **何时追问**：开启动态追问后，每次提交回答都会同步评估。如果评估给出追问，就把它作为一道 `FOLLOW_UP` 题插到当前题后面，下一题就是它，页面标为“追问”。
- **次数上限**：每道原题，压力面试最多追问 2 次，其他面试类型 1 次。追问之后再追问，算在同一道原题的额度里。追问题用 `parent_question_id` 记下原题。
- **关闭追问**：不插入任何题目，只答原定的题。
- **再练一次**：只复制原题，追问是针对上一次回答的，不复制。
- **报告**：追问显示在原题下面，标为“Q3 追问”。被问过的追问不再出现在“可能的追问”里。
- **插题实现**：题号分两步顺延，保证 `(session_id, order_no)` 始终唯一，H2 和 MySQL 都适用。

## 2. 回答思路

评估结果新增 `answerDirection`（40–160 字），说明这道题该怎么答：先讲什么、用哪段经历、补什么证据。

- 提示词要求只能提到简历、JD 和回答里已有的经历。
- 服务端会校验：回答思路里出现的每个数字，都必须能在回答、简历或 JD 里找到。找不到时只丢掉这条回答思路，评估照常保留。

## 4. 四个 AI 功能的真实模型检查（E-4）

| 功能 | 走通的流程 | 发现并已修复的问题 |
| --- | --- | --- |
| 岗位匹配 | 解析 → 分析（约 60 秒）→ 澄清 → 追问一轮 → 最终报告 | 见 [07](07-匹配评分与质量修复.md)：改写建议不合格时整份报告暂停；规则预估显示“可信度高”；软技能被标成硬性门槛；澄清选项的判定读错；追问没有轮次上限；理由里出现系统规则 |
| 职业规划 | 直达目标 → 生成能力树（31 个节点，98 秒）→ 专项测试出题（5 题，9 秒） | “我已确定目标职业”仍要走访谈；专项测试只是一个标签，不会出题 |
| 模拟面试 | AI 出题（13 秒）→ 回答 → 当场追问 → 回到原题 → 报告 | 追问不会被问到（见第 1 节） |
| 简历工作台 | 编辑器“润色经历”候选（7 秒）；工作台个人简介建议 | 第一次调用时上游偶发失败，只有一个通道就直接报错，日志里也看不到原因（见第 5 节）。个人简介建议和“自我介绍”润色在资料不足时会如实拒绝，这是预期行为 |

## 5. AI 网关的两处加固

- **重试**：只有一个通道时，遇到 408、429、5xx 或网络错误，等 600 毫秒后在同一通道再试一次。400 这类请求本身被拒的错误不重试。流式输出已经开始的请求也不重试。
- **日志**：上游返回非 2xx 时，记一条 WARN 日志，包含状态码、通道、模型和截断到 300 字的错误信息，不含 key 和提示词。以前这些信息被吞掉，只剩“AI 模型调用失败”。

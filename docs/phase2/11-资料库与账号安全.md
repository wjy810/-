# 资料库与账号安全：AI 建议、档案字段、引导页、绑定联系方式、安全通知

> 状态：已上线（V85）。修复审查中资料库、引导页和通知的五个问题。

## 1. AI 旧建议不再覆盖后来的修改

**改之前**：
- 打开“AI 优化”时，会直接复用这条经历最早一条“待确认”建议，哪怕它是几天前对着旧内容生成的。
- 采纳时带的是经历的**当前**版本号，版本校验总能通过。
- 结果：用户后来自己改过的经历要点，会被旧建议整段盖掉。

**现在**：
- **什么算“当前”**：经历的描述和核心成果，与建议生成时完全一致，这条建议才算当前。
- **用户改了这两项**：这条经历所有待确认的建议立即标为 `STALE`，不再展示，也不再复用。
- **其他途径改的内容**：比如另一个标签页改的、导入改的。列建议和采纳前都会再核对一遍，对不上的同样处理。
- **采纳过期建议**：返回 `CAREER_AI_CANDIDATE_STALE`，经历保持不变；窗口自动关闭，列表刷新。
- **采纳一条建议后**：同一经历其他基于旧内容的建议也一并作废。
- 列表接口支持 `status=STALE` 查询。

## 2. 保存档案不再清掉引导页写的字段

**改之前**：
- 引导页把“毕业时间”“专业”写进 `preferences`。资料库的档案表单只认识目标城市和办公方式，保存时整段替换，这两项就丢了。
- 引导页的目标岗位是自由文本，不更新岗位分类：改了岗位，分类还停在旧的。

**现在**：
- **服务端合并保存**：`basics`、`intentions`、`preferences` 三段都只替换请求里带的字段，其他字段保持原样；传 `null` 才会清掉一个值。
- **档案表单也带上原有字段**：表单里新增“毕业时间”“专业”两项，可以查看和修改引导页填过的内容。
- **引导页的目标岗位**改用资料库同一个岗位选择器，选定后一起保存岗位分类和三级分类 id，并在下方显示“岗位分类：……”。

## 3. 引导页有了入口

**改之前**：`/onboarding` 全站没有链接，注册后直接进工作台。

**现在**：
- 新注册的账号直接进入引导页（带着 `next` 注册的除外）。
- 工作台在还没有目标岗位时，显示“先花 1 分钟确定求职方向”，并提供“去设置”。
- 准备度清单的第一项在这种情况下改叫“确定求职方向”，点开就是引导页。
- 引导页的每一步都可以跳过，也可以“稍后再说，回到工作台”。

## 4. 可以绑定和更换邮箱、手机号

**改之前**：通知设置里的“去绑定邮箱”把人带到账号页，那里却写着“暂不支持绑定或更换联系方式”，后端也没有对应接口。用手机号注册的用户永远收不到邮件提醒。

**现在**：
- **接口**：`POST /api/v1/auth/contacts`，参数 `{channel, destination, verificationToken, currentPassword}`。
  - 新联系方式用验证码证明归属（用途 `CHANGE_CONTACT`）。
  - 用当前密码确认是本人操作。
  - 已被其他账号使用的，返回 `CONTACT_IN_USE`。
  - 其他用途的验证码不能拿来绑定。
- **账号页**：“登录信息与联系方式”分别列出邮箱和手机号，显示“已验证 / 未验证 / 未绑定”，并提供“绑定”或“更换”。
  - 弹窗依次是：填新联系方式、收验证码、填当前密码。
  - 验证通道没开时，会如实说明。
- **安全提醒先发**：安全通知在更换生效前发出，所以“邮箱已更换”这封邮件会寄到**原来的**邮箱，提醒的正是可能被他人操作的那个人。
- **通知设置里的“去绑定邮箱”**：跳到 `/account?bind=email`，直接打开绑定弹窗。
- **账号页顺带修正**：
  - “已验证”“账号状态”原来是写死的，现在按真实数据显示；注销处理中会如实标出。
  - 登录设备读取失败时显示“读取失败”，不再显示“仅当前设备”。

## 5. 账号安全通知会真的发出

**改之前**：通知类型里有 `SECURITY`，页面写着“不能关闭”，但没有任何地方发过。

**现在**：由 `SecurityNotices` 发出，类型 `SECURITY`，链接到“账号与安全”。每条都附“如果不是你本人操作……”的处理建议：

| 事件 | 通知 |
| --- | --- |
| 登录状态下修改密码 | 账号密码已修改 |
| 通过验证码找回并重置密码 | 账号密码已通过找回重置 |
| 退出其他设备（一台或全部） | 已退出一台登录设备 / 已退出其他 N 台登录设备 |
| 从没登录过的设备登录 | 新设备登录了你的账号（附设备，例如“Windows · Chrome”） |
| 绑定或更换邮箱、手机号 | 已绑定邮箱 / 邮箱已更换（附脱敏后的新旧联系方式） |

- **新设备登录的判断**：
  - 会话记下一个粗粒度的设备标签 `sessions.client_label`，例如“iPhone · 微信”，以及它的哈希 `client_hash`。
  - 不记 IP，也不记完整 User-Agent。版本号不计入，浏览器升级不算新设备。
  - 账号以前用已知设备登录过，而这次的设备从没出现过，才发提醒。
  - V85 之前的老会话没有设备记录，所以上线后的第一次登录只开始记录，不发提醒。
- **送达方式**：一直显示在通知中心，有已验证邮箱时同时发邮件。用户不能关闭这一类，通知设置页的说明已同步修改。
- **设备列表**：账号页的“登录设备”和“安全记录”显示设备标签，不再只写“其他登录会话”。

## 测试

- `CareerLibraryIT`（10 个，新增 2 个）：
  - 用户改过经历后，旧建议不再列出，也不能采纳；从其他途径改的同样拒绝。
  - 档案表单保存后，引导页写的字段保留。
- `AccountSecurityIT`（新增 2 个）：
  - 手机号账号绑定邮箱时，密码错误会被拒，成功后可以用邮箱登录。
  - 更换邮箱时，提醒发到原邮箱，原邮箱不能再登录。
  - 被占用的邮箱、其他用途的验证码都不能绑定。
  - 新设备登录、同类设备再次登录、退出其他设备、改密码、找回密码都按预期发通知，并发邮件到已验证邮箱；设备列表带设备标签。
- `LoginClientTest`：设备标签的解析，以及浏览器升级不算新设备。
- 前端：
  - 绑定弹窗：验证码、密码和失败提示。
  - 账号页：绑定状态、从通知设置跳来时直接打开绑定弹窗、设备列表读取失败的显示。
  - 档案表单：保留未知字段。
  - 经历：采纳过期建议时关闭窗口。
  - 引导页：岗位选择器连同分类一起保存。
  - 工作台：“确定求职方向”的入口规则。

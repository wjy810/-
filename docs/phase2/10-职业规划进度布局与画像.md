# 职业规划：验证回退、进度与布局、画像与推荐、任务换周

> 状态：已上线（V83）。修复审查中发现的四个问题。

## 1. 验证没通过，节点不再停在“待验证”

**改之前**：发起验证时节点变成“待验证”。之后无论是拒绝 AI 结果、确认“需要补强”还是确认“材料不足”，节点都一直停在“待验证”，只有验证通过才会改成“已掌握”。

**现在**：
- 发起验证时，验证记录会记下节点原来的状态，新增列 `career_ability_validations.previous_node_status`。
- 验证没有以“已掌握”收尾时，按下面的规则处理：

  | 结果 | 节点去向 |
  | --- | --- |
  | 确认通过 | 已掌握 |
  | 确认需要补强 | 学习中，并在当前周加一项补强任务 |
  | 确认材料不足 | 回到验证前的状态 |
  | 拒绝评估结果 | 回到验证前的状态 |

- 同一节点还有待确认的结果时，节点保持“待验证”。
- 只有当节点当前仍是“待验证”时才会回退；用户手动改过的状态不受影响。
- V83 之前的验证没有记录原状态，回退时按“学习中”处理。
- **补强任务排在用户现在所在的周**，以前是按“任务总数 ÷ 3”算出来的周。如果本周最后一个学习日已经过去，就排到下一周，但不超过计划的最后一周。
- **“待验证”按节点计数**：处于“待验证”的节点，加上还有结果待确认的节点；同一节点有两条结果只算一个。已拒绝的结果不再计入。
- 验证页的提示会说明节点去了哪里。

## 2. 拖动节点和学习进度不再生成新版本

**改之前**：
- 每拖一次节点就生成一个画布版本；任务开始、任务完成、发起验证、确认掌握也各生成一个版本。
- 版本号一变，待审的 AI 提案就被标成过期；正在跑的节点推演和批量验证在保存时会报“画布已更新”。
- 版本记录里堆满了“任务进度同步到能力节点”。
- 撤销或恢复旧版本时，学习进度也会跟着退回去。

**现在**，版本只记录内容；位置和学习进度属于画布的当前状态，直接写在最新版本上，不生成新版本：
- **位置**：拖动和“自动整理”改用新接口 `PUT /sessions/{id}/canvas/layout`，参数是 `{positions:[{nodeId,x,y}], resetNodeIds:[]}`。
  - 不需要传期望版本，也不会因为版本冲突失败。
  - 锁定的节点不能拖动（`CP_CANVAS_NODE_LOCKED`）。
  - 旧的批量接口只带 `resetLayout`、不改状态和锁定时，也走这条路径。
- **进度**：任务同步到节点的“学习中 / 待验证”，以及验证带来的“待验证 / 已掌握 / 回退”，都直接改最新版本的节点。
  - 保存进度时会重新读取当前画布，不再沿用验证开始前读到的旧画布，避免覆盖 AI 评估期间别处做的修改。
- **提案仍然有效**：采纳提案时，如果提案生成之后节点的进度已经变了，就保留当前进度，不用提案里的状态。
- **恢复旧版本**：恢复的是节点、关系和详情。每个节点保留当前的进度、位置和备注；已锁定的节点照旧不受影响。
- **撤销**：只撤销内容版本。拖动不算一步，可以直接拖回去，或者用“自动整理”。
- 节点编辑、批量改状态、新增、删除、拆分、合并、采纳提案、恢复版本，这些内容修改仍然各生成一个新版本。

## 3. 打开画像不再悄悄作废推荐

**改之前**：
- 在推荐阶段打开“画像”，点“保存草稿”或“选择资料授权”，都会无条件保存一次。即使什么都没改，画像也会退回草稿，现有推荐被作废，重新生成又要多扣一次额度。
- 资料授权同理：选择没变也会作废推荐。
- 状态栏在推荐阶段显示“修改后自动保存”，但这个阶段其实不会自动保存。

**现在**：
- **没改就不保存**：前端发现表单没有变化时不发请求。
- **服务端兜底**：画像和资料授权的内容与当前一致时，接口原样返回。画像状态、确认标记和推荐都保持不变。
  - 画像起草阶段保存相同的资料授权，照样进入“资料范围已保存”这一步。
- **作废推荐前先确认**：已有推荐时，真正修改画像或资料授权，会先弹窗说明“现有 N 个职业方向会失效，需要重新核对确认后再生成，成功后消耗 1 次 AI 额度”。选“先不保存”就什么都不变。
- **打开时的提示**：在核对或推荐阶段打开画像，表单上方会说明“只查看不会影响现有推荐”，并提供“返回职业方向”或“返回画像核对”。有未保存的修改时，返回前会先确认是否放弃。
- **状态如实显示**：只有起草阶段会自动保存，状态栏显示“修改后自动保存”。其他阶段显示“有未保存的修改”或“没有未保存的修改”，按钮改为“保存修改”。

## 4. 任务换周后截止日跟着变

**改之前**：把任务拖到其他周，截止日不变，常常落在任务所在周之外。

**现在**：任务换周且没有指定日期时，截止日改为新周的最后一个学习日，算法与生成计划时相同（`weekDueDate`）。移动后的提示会写明新的截止日。

## 测试

- `CareerPlanningIT`（9 个，新增 2 个）：
  - 拖动不生成版本，锁定节点不能拖。
  - 任务进度不生成版本，待审提案仍为草稿，采纳时保留新进度。
  - 换周重算截止日。
  - 拒绝后回到学习中，“待验证”计数归零。
  - 需要补强时排进当前周。
  - 恢复旧版本时保留进度和位置。
  - 画像和资料授权原样保存时推荐不变，真正修改后才作废推荐。
  - 原有用例改为断言：批量验证不生成新版本。
- `CareerPlanScheduleTest`：补强任务排在哪一周。
- 前端：
  - 画像页：只查看不发请求、可以返回职业方向、修改后先确认再保存。
  - 画布：拖动和自动整理调用 layout 接口，不进入撤销记录。

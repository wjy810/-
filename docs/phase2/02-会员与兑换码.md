# 会员套餐与兑换码

> 状态：第一版已上线（V74）。本文记录收费模式、权益边界、兑换码的安全设计和接口。在线支付尚未接入，见第 6 节。

## 1. 为什么这样收费

求职是强季节性的：秋招、春招前后两三个月最密集，其余时间几乎不用。所以采用**免费版长期可用 + 专业版按时长开通**，不做自动续费的订阅：

- **免费版要真的够用。** 投递看板、查看回执、全部模板、PDF 导出永远免费。这些是让用户留下来、并通过分享链接带来新用户的部分（每条专属链接的页脚都有“也在找工作？”入口）。
- **专业版卖“密集期的量”。** 只提高两个有真实成本或真实稀缺的额度：每月 AI 次数（模型调用成本）和同时有效的专属链接数（密集投递时才需要）。
- **B2B2C 是主渠道。** 高校就业指导中心和培训机构按届采购兑换码发给学生。学校有预算、有就业率考核，学生零门槛开通，平台一次触达整届用户。兑换码也用于官方活动和合作推广。

## 2. 套餐与权益

| 权益 | 免费版 | 专业版 |
| --- | --- | --- |
| 每月 AI 次数（岗位匹配、简历 AI 建议等） | `jobproof.ai.workbench.monthly-quota`（默认 50） | `jobproof.membership.pro.ai-monthly-units`（默认 300，不会少于免费版） |
| 同时有效的专属简历链接 | `jobproof.membership.free.active-links`（默认 3） | `jobproof.membership.pro.active-links`（默认 20） |
| 查看回执、投递看板、漏斗与提醒 | 包含 | 包含 |
| 全部简历模板与 PDF 导出 | 包含 | 包含 |
| 隐藏联系方式、链接有效期与撤回 | 包含 | 包含 |

数字全部由服务端下发（`GET /api/v1/membership/plans`），前端不写死任何额度。

价格（单位：分，展示时换算）：月付 1900 / 30 天，季付 4900 / 90 天，年付 16800 / 365 天。价格页按“约 ¥X/月”和“比月付省 N%”展示。

规则：

- **升级当月立即补足 AI 次数**：本月额度按套餐重新计算，差额以 `plan-upgrade:<月份>` 记入 AI 用量流水，已用次数不清零。
- **到期自动回到免费版，数据全部保留**：已经发出的专属链接在各自有效期内继续可用、不会被撤回；有效链接降到免费版上限以内之前不能再新建。
- **可叠加**：已是专业版时再兑换，从当前到期日之后顺延，而不是从今天算起。
- **到期提醒**（V75）：到期前 7 天发一次“专业版还有 N 天到期”，到期后发一次“专业版已到期，已回到免费版”。每个到期日每种提醒只发一次，续期会重新计时；最近一周内才开通或续期的（如 7 天码）不发提前提醒；到期超过 3 天才扫到的不再补发。扫描每 5 分钟一次（`jobproof.reminders.*`），先用条件更新认领再发通知，多实例下也只发一次。
- 运营账号（管理员）没有会员；兑换和会员页对其关闭。

## 3. 兑换码

格式 `JP-XXXX-XXXX-XXXX-XXXX`：16 位，字母表去掉了容易看错的 `0 O 1 I L`（31 个字符，约 79 位熵）。输入宽容：大小写、空格、短横线、是否带 `JP` 前缀都可以。

安全设计：

- **只存哈希。** 库里保存 `sha256(规范化后的码)` 和末 4 位提示；明文只在生成批次的那一次响应里返回，管理端必须当场复制或下载 CSV（关闭前未保存会二次确认）。数据库泄露也拿不到可用的码。
- **防猜测。** 每个账号每小时最多 10 次失败尝试（`redeem_attempts`），超过返回 429 `REDEEM_TOO_MANY_ATTEMPTS`。失败记录在兑换事务回滚之外写入（`noRollbackFor`），不会因为抛错而丢失。
- **防重复兑换。** 认领是一条带条件的 `UPDATE … WHERE redeemed_by IS NULL`，并发下只有一个账号能成功；同一账号重复提交得到“你已经兑换过这个码”，不消耗尝试次数。
- **会员行加锁。** 延长有效期前先 `INSERT` 占位（主键冲突忽略），再 `SELECT … FOR UPDATE`，两次并发兑换不会互相覆盖到期日。
- **批次管理。** 每批 1–500 个，时长只能是 7/30/90/180/365 天，可设兑换截止时间；名单外流时可一键停用整批未使用的码，已兑换的会员不受影响。生成、停用、兑换都写入审计日志。
- CSV 导出对每个单元格加引号，并在以 `= + - @` 开头的内容前加 `'`，防止在表格软件里被当作公式执行。

## 4. 前端

| 页面 | 路径 | 说明 |
| --- | --- | --- |
| 套餐与价格 | `/pricing` | 公开页（未登录也可见，落地页导航与页脚有入口）；月付/季付/年付切换；权益对比；高校与机构合作；常见问题 |
| 会员与兑换 | `/account/membership` | 当前套餐与剩余天数、本月 AI 次数与有效链接用量、兑换码输入（边输边分组）、套餐对比、开通记录；`#redeem` 直达输入框 |
| 兑换码运营 | `/admin/redeem-codes` | 管理员：批次统计、新建批次、一次性展示明文（复制全部 / 下载 CSV）、兑换进度、停用 |

**额度用尽时的升级引导**：API 客户端识别 `AI_QUOTA_INSUFFICIENT` 和 `RESUME_LINK_LIMIT` 两类拒绝，交给全局处理器；处理器只对**免费版**账号弹出一次带“了解专业版”按钮的提示（专业版账号到上限不推销）。记录投递时如果因链接上限失败，对话框里直接给出“先不附链接，直接记录”，填好的内容不会丢。

## 5. 数据与接口

表（V74）：`account_memberships`（每账号一行：套餐、到期时间、来源）、`membership_events`（开通记录）、`redeem_code_batches`、`redeem_codes`（哈希、提示、兑换人与时间）、`redeem_attempts`。

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/api/v1/membership/plans` | 公开：套餐权益与价格 |
| GET | `/api/v1/membership` | 当前套餐、权益、有效链接数、开通记录 |
| POST | `/api/v1/membership/redeem` | 兑换 `{ code }` |
| GET / POST | `/api/v1/admin/redeem-codes` | 管理员：批次列表 / 生成批次（响应里含明文） |
| POST | `/api/v1/admin/redeem-codes/{id}/revoke` | 管理员：停用批次 |

数据权利：会员状态和开通记录纳入账号导出（模块 `membership`）；注销账号时删除会员与开通记录，已兑换的码保留为“已使用”，兑换人替换为全零 ID，批次的兑换统计不受影响。

## 6. 下一步

1. **在线支付**：接入微信支付 / 支付宝的 Native 或 JSAPI 下单。支付成功回调与兑换码走同一个 `extend()`，来源记为 `ORDER`；订单表单独建，回调验签、幂等（以商户订单号为键）。价格页按钮从“使用兑换码开通”切换为“立即购买”。
2. **机构后台**：给合作机构一个只读视图（本机构批次的兑换进度、按周的活跃人数），不暴露任何个人信息。
3. **邀请奖励**：用户的分享链接带来注册时，双方各得 7 天专业版（复用 `extend()`，来源 `REFERRAL`，按设备与账号去重）。

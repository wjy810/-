## 1. 选型原则

1. **所见即所得是硬约束**：屏幕预览、模板缩略图、导出 PDF 必须出自同一份 HTML/CSS 和同一套字体。任何“两套渲染器各自近似”的方案直接否决。
2. **ATS 可读性不能被设计牺牲**：导出 PDF 的文字层必须可选、可复制、按阅读顺序提取；字体以 CID TrueType 嵌入。
3. **复用一期资产**：Vue 3 + TypeScript、Spring Boot 3.5 + Java 21、PDFBox、任务队列与 Outbox 继续使用；新增依赖必须对应一个明确能力。
4. **可在 2 核 2G 单机上运行**：新增服务要给出内存上限和并发策略。
5. **每个结论都有验证**：本文标注“已验证”的结论都在开发环境用真实代码跑通过（见 §8）。

## 2. 现状问题（简历模板与导出）

| # | 问题 | 证据 | 影响 |
| --- | --- | --- | --- |
| T1 | 预览与 PDF 是两套渲染器 | 预览：`ResumeTemplatePreview.vue`（HTML/CSS）；PDF：`ResumeStructuredPdfRenderer.java`（PDFBox 逐行画字，766 行） | 导出结果与屏幕不一致：字重、行距、边距、分栏高度、断行全都不同（实测对比见重构方案 §2.1） |
| T2 | PDF 只有一个字重 | `NotoSansSC-Regular.ttf` 单字重；标题、姓名、公司名无法加粗 | 层级感缺失，观感廉价 |
| T3 | PDF 断行错误 | 自写 `wrap()` 按宽度切字符串，中英混排在词中间折行（如“具备 Java / 后端开发”） | 读起来像排版事故 |
| T4 | 预览依赖用户电脑字体 | `--resume-font: "Microsoft YaHei", ...` / `"SimSun", ...` | 不同电脑看到的版式不同，也和 PDF 不同 |
| T5 | 分页靠“容量单位”估算 | 前端 `resumePreviewPagination.ts`、后端 `deterministicUnits()` 按字符数估算高度 | 预览页数与 PDF 页数不一致；“溢出”判断不可信却会阻止导出 |
| T6 | 模板只是参数组合 | 12 套模板 = 同一骨架 × 分栏比例 × 4 种页头 × 5 种标题样式 × 2 种颜色（JSON `resume-layout-v3`） | 千篇一律，无法做出有个性的版式（时间轴、编号章节、水墨装饰等） |
| T7 | 模板是演示数据 | 状态全部为 `DRAFT`，靠 `jobproof.templates.demo-enabled` 开关显示；生产配置关闭 | 生产环境没有可用模板 |
| T8 | 渲染发生在数据库事务内 | `ResumeService.completePdfExport` 标注 `@Transactional` 并在其中渲染 | 换成外部渲染后会长时间占用连接 |
| T9 | 简历上印品牌标记 | 页头无照片时显示 `JP` 字样（`showMark`） | 用户简历出现产品水印，不专业 |

## 3. 总体结论

| 关注点 | 选型 | 说明 |
| --- | --- | --- |
| 渲染方式 | **统一 HTML/CSS 渲染器**（Vue 组件），预览与打印共用 | 解决 T1、T4 |
| PDF 引擎 | **Chromium 无头打印**，通过 `playwright-core` 驱动，自建渲染服务 `renderer/` | 已验证：中文排版、字重、可提取文字层、链接可点击 |
| 字体 | **Fontsource 静态字重 woff2**（OFL）：Noto Sans SC、Noto Serif SC、Inter、Source Serif 4、JetBrains Mono | 静态字重以 CID TrueType 嵌入；可变字体会被 Chromium 嵌成 Type 3（已验证），ATS 兼容差 |
| 分页 | **自研测量式分页**：在真实尺寸页面中测量每个内容块高度，按区域贪心装箱 | 预览与打印在同一引擎中跑同一段代码，页数一致；解决 T5 |
| 模板形态 | **代码模板 + 数据清单**：版式是 Vue 组件 + 作用域 CSS；清单（名称、分类、配色、字体组合、能力）存数据库 | 解决 T6；运营仍可在后台上下架、调整排序与配色 |
| 渲染服务运行时 | **Node 22 原生 TypeScript**（类型剥离，免编译）+ `node:http` | 无 Web 框架依赖，单文件可读 |
| 后端调用 | `java.net.http.HttpClient`（虚拟线程） | 无新增依赖 |
| ATS 校验 | **PDFBox 文本提取**（已有依赖） | 导出后自动核对姓名、联系方式、各板块标题是否按顺序可提取 |
| 装饰素材 | **AI 生成栅格**（纸纹、水墨、水彩、极光、线描）+ **手写 SVG**（网格、几何、图标） | 栅格经人工 + 脚本校验透明度与均匀度后导出 WebP |
| 预览缩放 | 真实尺寸（210 × 297mm）排版，外层 `transform: scale()` 缩放 | 缩放不改变断行，屏幕所见即打印所得 |

## 4. 关键决策与备选方案

### 4.1 PDF 引擎

| 方案 | 结论 | 理由 |
| --- | --- | --- |
| 继续 PDFBox 手绘 | ❌ | 需要自行实现断行、中文标点禁则、字重、分栏、图片、链接；永远追不上浏览器排版，且与预览两套逻辑 |
| OpenHTMLtoPDF / Flying Saucer | ❌ | 只支持 CSS 2.1，没有 Flex/Grid；中文断行与字体回退弱；仍与预览引擎不同 |
| wkhtmltopdf | ❌ | 已停止维护，内核为旧版 QtWebKit |
| Gotenberg（Chromium 容器） | ❌ | 通用转换接口，不能复用常驻页面与渲染钩子，每次冷启动页面；镜像约 1GB |
| **playwright-core + 系统 Chromium，自建渲染服务** | ✅ | 与用户浏览器同内核；常驻页面复用（实测单页 PDF 120–180ms）；可拦截所有网络请求防止 SSRF；支持带标签 PDF 与链接注释 |

版本策略：`playwright-core` 与 Chromium 版本锁定，渲染器协议版本 `resume-render-v4` 写入每份导出的元数据；升级 Chromium 视为渲染器升级，需要跑模板回归（§4.6）。

### 4.2 字体

| 方案 | 结论 | 理由 |
| --- | --- | --- |
| 系统字体（微软雅黑 / 宋体） | ❌ | 因设备而异；服务器上没有；商用授权不明确 |
| 可变字体（`@fontsource-variable/*`） | ❌（仅用于界面） | Chromium 打印时嵌入为 Type 3 字体，部分 ATS 与 PDF 阅读器提取文字不稳定（已验证） |
| **静态字重（`@fontsource/*`）** | ✅ | 嵌入为 CID TrueType + ToUnicode（已验证）；按 unicode-range 切片，浏览器只下载用到的字 |
| 思源 / Noto 以外的中文字体（如霞鹜文楷） | 暂缓 | 无 npm 发行包，自托管切片成本高；后续可作为扩展字体组合 |

字体组合（模板可声明支持哪些组合）：

| 组合 ID | 中文 | 西文 | 用途 |
| --- | --- | --- | --- |
| `sans` | Noto Sans SC 300/400/500/700 | Inter 400/500/600/700 | 现代、清晰 |
| `serif` | Noto Serif SC 400/600/700 | Source Serif 4 400/600/700 | 经典、学术、国风 |
| `mixed` | 标题 Noto Serif SC，正文 Noto Sans SC | 标题 Source Serif 4，正文 Inter | 编辑感 |
| `tech` | Noto Sans SC | Inter + JetBrains Mono（日期、标签） | 工程师 |

体积控制：字体只在简历相关页面按需加载（路由级拆包）；每个字重的中文切片约 100 个，单页简历实际下载约 0.6–1.2MB，浏览器缓存后复用。

### 4.3 分页

| 方案 | 结论 | 理由 |
| --- | --- | --- |
| 按字符数估算（现状） | ❌ | 不可能与真实排版一致 |
| CSS 多栏 / 浏览器原生分页 | ❌ | 屏幕上无法看到分页结果；双栏版式各栏独立流动做不到 |
| Paged.js | ❌ | 体积大、处理慢，维护停滞；对“侧栏与主栏各自跨页”的版式支持差 |
| **测量式分页（自研，约 300 行）** | ✅ | 把内容拆成块（板块标题与首条目绑定、条目整体不拆、超长条目按要点拆），在真实宽度下测量高度后贪心装箱；规则简单、可单测 |

### 4.4 模板形态

| 方案 | 结论 | 理由 |
| --- | --- | --- |
| 纯 JSON 参数（现状 v3） | ❌ | 表达力不够，所有模板长得一样 |
| 管理员上传 HTML/CSS | ❌（本期） | 存在 XSS 与外链风险，需要沙箱与审核流程；本期先把内置模板做好 |
| **代码模板 + 数据清单** | ✅ | 版式质量由设计与代码评审保证；清单可运营（上下架、默认配色、排序、推荐标签） |

### 4.5 渲染服务

- **运行时**：Node 22（类型剥离直接运行 `.ts`，已验证 `process.features.typescript === 'strip'`）。
- **HTTP**：`node:http`，不引入 Express/Fastify；接口只有 3 个（§架构 5.3）。
- **浏览器管理**：单个 Chromium 进程 + 页面池（默认 2 个常驻页面）；页面崩溃自动重建；连续失败 3 次重启浏览器。
- **安全**：打印页只允许加载本地打包资源，其他所有请求在 `page.route('**')` 中拒绝；照片以 data URL 传入；接口用共享令牌鉴权；请求体上限 2MB。
- **内存**：容器上限 512MB，页面池 2；超过并发的请求排队，排队超过 20 秒返回 503。

### 4.6 质量门禁

| 检查 | 工具 | 何时运行 |
| --- | --- | --- |
| 模板渲染回归 | 渲染服务 + 示例简历（中文完整、英文、极少内容、超长内容 4 份） | CI；每个内置模板 × 每个配色 |
| 页数与溢出 | 渲染结果 `pageCount` | CI + 每次导出 |
| ATS 文本提取 | PDFBox `PDFTextStripper` | CI + 每次导出（结果写入导出记录） |
| 对比度 | 配色清单计算 WCAG 对比度（正文 ≥ 4.5:1，次要文字 ≥ 3:1） | 单测；用户自定义颜色时前端实时校正 |
| 像素回归 | 渲染 PNG 与基线对比（容差 0.5%） | CI，可选 |

## 6. 部署影响

| 项 | 一期 | 二期 |
| --- | --- | --- |
| 容器 | nginx、api、mysql、redis、minio、clamav | + `renderer`（仅内网，端口 3100） |
| 内存预算（2G 机器） | api 768MB、mysql 512MB、redis 64MB、minio 128MB | renderer 384–512MB；clamav 改为按需或外置（见架构 §8） |
| 配置 | — | `JOBPROOF_RENDERER_URL`、`JOBPROOF_RENDERER_TOKEN`；渲染服务 `RENDERER_TOKEN`、`RENDERER_POOL_SIZE`、`RENDERER_CHROMIUM_PATH` |
| 失败策略 | — | 渲染服务不可用时导出任务失败并提示“排版服务暂时不可用”，可一键重试；不回退到旧 PDFBox（避免产出与预览不一致的文件） |

## 7. 风险与对策

| 风险 | 对策 |
| --- | --- |
| Safari / Firefox 与 Chromium 断行有细微差异 | 导出前在对话框展示服务端渲染的第一页缩略图；以 PDF 为准；国内主流浏览器均为 Chromium 内核 |
| 中文字体体积 | 切片按需加载；仅简历相关路由加载；Service Worker 缓存（后续） |
| Chromium 安全更新 | 镜像按月重建；渲染器协议版本随之递增并跑回归 |
| 旧模板与旧冻结版本 | 已冻结的历史版本保留原 PDFBox 渲染路径（只读、不再改进）；可编辑简历迁移到新模板（映射见架构 §7） |
| 渲染服务成为单点 | 无状态，可水平扩展；后端请求带超时与 2 次重试；任务失败可重试 |

## 8. 已验证的结论

| 结论 | 验证方式 | 结果 |
| --- | --- | --- |
| Chromium 打印中文网络字体 | `playwright-core` 打开本地 HTML（`file://`），等待 `document.fonts.ready` 后 `page.pdf()` | 字重 300/400/600/700 正确，单页 126–182ms |
| 静态字重嵌入方式 | `pdffonts` | `CID TrueType / Identity-H / uni=yes` |
| 可变字体嵌入方式 | `pdffonts` | `Type 3`（因此不用于打印） |
| 文字层可提取 | `pdftotext -layout` | 姓名、联系方式、正文按阅读顺序输出，无断词 |
| `setContent` 无法加载本地字体 | 同上，字体数为 0、回退文泉驿 | 打印页必须以 `file://` 或本地静态服务加载 |
| 生图接口可用于素材 | 26 张素材（纸纹、水墨、水彩、线描、光晕） | 全部真透明背景（透明像素 48–97%），纸纹 6 倍对比度拉伸后无暗角、无污点 |

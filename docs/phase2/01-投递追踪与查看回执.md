# 投递追踪与简历查看回执

> 状态：第一版上线于 V73，第二版上线于 V80，第三版上线于 V84。
>
> - 第二版改了五处：回执汇总、本人打开识别、链接到期规则、下一步完成、归档。
> - 第三版改了四处：归档停用链接、“想投”不生成链接也不记投递日期、通用链接可完整管理、本人设备标记 30 天到期且退出登录即清除，见第 7 节。
>
> 本文记录要解决的问题、产品形态、数据与隐私边界，以及盈利设计。

## 1. 要解决的问题

求职者把简历投出去以后，最大的焦虑是“石沉大海”：不知道对方有没有看、看了多久，也不知道该不该跟进。现有招聘平台只在自己的站内显示“已读”，邮件投递、内推、校招宣讲会、猎头渠道则完全没有反馈。

JobProof 已经有“冻结版本”（导出 PDF 时自动生成的不可变快照）。在它之上，可以给**每家公司一条专属简历链接**：对方点开时，求职者立刻知道。

## 2. 产品形态

| 能力 | 说明 |
| --- | --- |
| 投递看板 | 阶段：想投 → 已投递 → 笔试/测评 → 面试中 → Offer → 已结束。<br>结束的结果有接受、婉拒、未通过、主动放弃、没有回应；**接受和婉拒只对到过 Offer 的投递开放**。接受 Offer 后，会询问是否把其他进行中的投递一起结束。<br>桌面端拖拽移动。手机（≤640px）上看板改成按阶段折叠的列表，用“移动到…”菜单切换阶段 |
| 筛选与归档 | 可按阶段、渠道、“下一步已逾期”“简历被打开过”筛选；列表可按更新时间、下一步时间、投递日期、公司排序。<br>“删除”改为**移入归档**：归档后的投递不出现在看板、统计、提醒和周报里，**它的专属链接随之停用**（对方打开看到“链接已停用”，不计回执、不发提醒、不占名额）。可以恢复（链接一并恢复），也可以从归档中彻底删除。<br>30 天内重复记录同一公司、同一岗位时，会先提醒 |
| 专属简历链接 | 记录投递时选择冻结的简历版本，即可生成 `/r/{token}`。“想投”阶段不生成链接，也不记投递日期；改成“已投递”时记为当天，并提示生成链接。<br>可隐藏手机号、邮箱和照片。有效期可选 7、30、60、90 天或长期，默认 60 天。<br>**有效期和“隐藏联系方式”可以就地修改，链接地址不变**；只有换简历版本才需要生成新链接，旧链接立即失效。<br>投递结束后，链接再保留 14 天，之后自动失效，不再占用有效链接名额 |
| 查看回执 | 打开次数、读者人数（可看出简历被转给了新的人）、每次打开的设备与应用（微信、企业微信、钉钉、飞书、QQ、浏览器）、来源域名、实际阅读时长。<br>卡片、漏斗和详情**汇总这条投递用过的所有链接**，换链接后旧回执不会“消失”。<br>每条打开记录都可以标记“是我自己”，标记后从回执里去掉 |
| 链接总览 | 投递追踪的“链接”视图列出全部专属链接（含已撤回、已过期、已停用），可筛选有效 / 通用；每条可复制和预览（仅限能打开的链接）、改名、改有效期、隐藏联系方式、过期后重新启用、展开打开记录并标记“是我”、撤回。“通用链接”不属于某次投递，适合招聘会、内推群、个人主页，同样统计回执；它的提醒直达这里（`/applications?tab=links`） |
| 提醒 | 首次打开、出现新的读者（可能被转给面试官）时发站内通知，直达这条投递；下一步（笔试、面试）开始前 24 小时内提醒一次，改了时间会重新提醒，刚设置的 10 分钟内不提醒（V75） |
| 漏斗 | 已投递 → 简历被打开 → 进入面试 → 拿到 Offer，每一步相对上一步的转化率；“最远到达的阶段”单独记录，结束的投递仍计入它走到过的阶段 |
| 下一步 | 每条投递可记下一步和时间，看板按最近的下一步排序，逾期标红。<br>做完后点“已完成”，可附一句结果（如“进入二面”），写进时间线，之后不再显示逾期。<br>工作台分开显示“接下来”和“已过时间待更新” |
| 关联 | 可关联岗位匹配（显示匹配分）、所用简历版本；岗位匹配报告页可“记录投递”带入公司与岗位；进入笔试 / 面试阶段后，详情里可一键“模拟面试”（有岗位匹配时按报告出题，否则带入公司与岗位） |

公开页对访客：

- 不需要登录。
- 不被搜索引擎收录：接口返回 `X-Robots-Tag`，nginx 对 `/r/` 加 `X-Robots-Tag: noindex` 和 `no-store`，页面带 `meta robots`。
- 页脚说明会记录什么（时间、设备、App、来源网站、阅读时长、随机读者标识）、不记录什么（IP）。
- 求职者隐藏了联系方式时，提示 HR 通过收到简历的渠道回复。
- 可以“打印 / 存为 PDF”；在微信内置浏览器里，会提示先“在浏览器打开”。
- 底部有“也在找工作？”入口，每一次分享都是一次自然曝光。

## 3. 数据与隐私边界

- **不使用访客 IP**：分享页给浏览器发一个随机的第一方 cookie `jp_reader`，作用域只限分享接口。库里只保存 `sha256(链接 ID | 读者 cookie | User-Agent)`，用来区分“同一个人刷新”和“新的读者”。第一版用的是地址，同一个公司网络下的不同 HR 会被当成同一个人，第二版不再使用地址。
- **不计入的访问**：
  - 求职者自己打开：已登录时按会话识别；被标记过“是我自己”的读者也不计入。
  - 在打开过投递追踪的浏览器上，按 `jp_owner_device` cookie 识别：库里只存哈希。cookie 有效期 30 天，每次打开投递追踪续期；服务端也只认 30 天内用过的登记。在这台浏览器退出登录即清除；“退出其他设备”清掉其他浏览器的登记；改密码或找回密码清掉全部；注销账号时删除。
  - 搜索引擎与链接预览抓取：按 User-Agent 识别。
  - 同一读者 30 分钟内的刷新：算作同一次阅读。
  - 刷量：每条链接每小时最多记录 120 次。
- **阅读时长**：只在页面可见、并且最近 30 秒内有滚动、点击或按键时累计，后台挂着的标签页不算阅读。单次上限 30 分钟；页面关闭时用 `sendBeacon` 补发。心跳必须带上打开时下发的随机密钥（库里只存它的哈希），时长只增不减。
- **数据权利**：
  - 投递、时间线、链接与回执纳入账号导出。
  - 注销账号时全部删除（含本人设备记录），链接立即失效。
  - 从归档中彻底删除一条投递时，连同它的链接与回执一起删除。
- 链接令牌为 128 位随机值。令牌以明文保存，是为了让求职者随时再次复制链接；它只授权读取这一份冻结版本，不授权任何账号操作。

## 4. 接口

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/api/v1/job-applications` | 看板数据与漏斗统计 |
| GET | `/api/v1/job-applications/resume-versions` | 可分享的冻结版本 |
| GET / POST / PUT / DELETE | `/api/v1/job-applications/{id}` | 详情（含时间线、链接、回执）/ 新建 / 编辑 / 彻底删除 |

| POST | `/api/v1/resume-links/{id}/revoke` | 撤回 |

| GET | `/api/v1/public/resume-links/{token}` | 公开：读取简历 |
| POST | `/api/v1/public/resume-links/{token}/views` | 公开：开始一次阅读 |

旧的投递模块（V4，`/api/v1/applications`）已在 V25 下线，其数据作为只读历史保留在资料库里；新模块使用独立的表与路径，互不影响。

## 5. 盈利设计

已在 V74 实现，见 [02-会员与兑换码](02-会员与兑换码.md)。与本模块相关的只有一项额度：**同时有效的专属链接数**。免费版 3 条，专业版 20 条，都可以配置。投递结束 14 天后链接自动失效，归档的投递链接立即停用，“想投”不生成链接，所以免费版的 3 条名额按“正在进行的投递”周转，不会到第 4 家就卡住。查看回执的全部内容（读者数、设备与应用、阅读时长、转发提醒）、隐藏联系方式和链接有效期对免费版同样开放——回执是让用户留下来并带来新用户的部分，不作为收费点。

渠道：个人按时长开通；高校就业中心与培训机构批量采购兑换码（B2B2C）。

## 6. 周报口径（V80 修正）

- **投递数**：按投递日期统计，不算“想投”，也不算已归档的投递。
- **简历被打开**：不算已归档投递的链接（V84）。
- **进入下一轮**：只算向前推进到笔试、面试或 Offer 的投递。同一条投递在一周里推进多次只算一次；重新打开已结束的投递不算推进。
- **跟进建议**：只有确实有公司打开过简历时，才提示“跟进打开过简历的公司”。

## 7. 第三版（V84）

### 7.1 归档停用链接

**改之前**：归档只是把投递从看板上拿掉。它的链接照样公开，照样占名额；HR 打开时照样推送提醒，并计入周报。

**现在**：
- **归档**：给这条投递的链接记上 `resume_share_links.suspended_at`。
  - 公开页返回 `RESUME_LINK_SUSPENDED`，显示“求职者已停用这个链接”。
  - 不计回执，不发提醒，不占有效链接名额，周报也不再统计。
  - 归档中的投递不能生成新链接（`APPLICATION_ARCHIVED`）。
- **恢复**：名额够时链接一并恢复，地址不变；已过期的恢复后仍是过期状态。名额已满时链接保持停用，时间线和提示会说明原因；撤回不用的链接后，在详情或链接总览里点“重新启用”（`PATCH {reactivate:true}`）。
- **详情抽屉**：从通知或归档打开已归档的投递时，显示“从归档恢复”，并说明链接已停用，不再提供“生成专属链接”。
- **迁移**：V84 把已经归档的投递的链接全部停用；导出里增加 `archived_at` 和 `suspended_at`。

### 7.2 “想投”

**改之前**：“想投”也默认生成 60 天链接，免费版收藏 3 家名额就满了。投递日期预填收藏当天，改成“已投递”后也不变，周报和排序因此算错周。

**现在**：
- 记录为“想投”时：
  - 不生成链接，不记投递日期，前端和后端都这样处理；
  - 表单里简历选择改叫“打算投的简历”，并说明原因。
- 改成“已投递”或之后的阶段时，投递日期记为当天，看板会提示“生成链接”。
- 从未投出过的投递，编辑时也不保存投递日期。
- V84 清掉了现有“想投”记录里预填的日期。

### 7.3 通用链接的管理

**改之前**：链接总览里只能复制、预览、看打开记录和撤回。通用链接没有“是我”、改有效期、隐藏联系方式和过期重新启用；已撤回、已过期的链接还显示“预览”。

**现在**：
- **设置**：可以修改名称、有效期和隐藏联系方式，链接地址不变。
- **过期链接**：按钮变成“重新启用”，设置新的有效期即可。
- **已停用的链接**：可以直接“重新启用”。
- **打开记录**：每条都有“是我”，点了就从回执里去掉。
- **只能打开的链接**才显示“复制”和“预览”。
- **不能打开的链接**会写明原因：已过期、已撤回，或投递已归档。
- 这些操作同样适用于投递专属链接。

### 7.4 本人设备标记

**改之前**：`jp_owner_device` 的有效期是 365 天，退出登录也不清除。在机房或别人的电脑上用过一次，一年内这台电脑上的打开都不计回执。

**现在**：
- **有效期**：cookie 30 天，每次打开投递追踪续期。服务端只认 30 天内用过的登记（`OWNER_DEVICE_TTL`），已经发出的老 cookie 也会到期。
- **退出登录**：清除 cookie，并删除这台浏览器的登记。
- **退出其他设备**：删除其他浏览器的登记，保留当前这台。
- **改密码、找回密码**：全部删除。
- **实现方式**：身份模块通过 `shared.auth.SignOutListener` 通知各模块，不依赖投递模块；某个模块处理失败不影响退出。

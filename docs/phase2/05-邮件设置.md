# 后台邮件设置

> 状态：第一版已上线（V77，`/admin/mail-settings`）。

## 1. 为什么要做

注册验证码和提醒邮件原来只能通过服务器环境变量配置：换邮箱、换授权码都要登录服务器、改文件、重启；配置对不对，只能等真实用户收不到邮件才知道；发送失败也只记在数据库里，后台看不到。

## 2. 页面

**后台 › 邮件设置**：

- **当前状态**：正在使用后台配置 / 服务器环境变量 / 还没有可用账号；保存的授权码无法解密时（例如更换了主密钥）明确提示并暂停发信；提醒邮件是否开启。
- **SMTP 账号**：一键填写常用邮箱（QQ 邮箱、腾讯企业邮、网易 163、阿里企业邮、Outlook / 365）的服务器、端口和加密方式，并给出开启 SMTP、获取授权码的位置；填写账号、授权码、发件地址与名称；“发送提醒邮件”总开关（只管提醒邮件，验证码不受影响）。保存后立即生效，不需要重启。
- **发送测试邮件**：用当前生效的账号给指定邮箱发一封；失败时说明原因（授权码不对、找不到服务器、连接超时、加密方式不匹配、被拒收），最近一次结果会保留。
- **提醒邮件发送情况**：近 24 小时已发送、待发送 / 重试中、近 7 天失败，以及最近 20 封的收件人（打码）、主题、状态和失败原因。
- **恢复为环境变量**：删除后台配置，回到服务器环境变量中的账号。

## 3. 规则

- **优先级**：后台保存了账号就用后台的，否则用环境变量（`QQ_SMTP_USER`、`QQ_SMTP_AUTH_CODE`、`MAIL_FROM` 等，已有部署无需改动）。验证码与提醒邮件共用同一个账号。
- 后台保存的账号带有自己的“提醒邮件”开关；只用环境变量时，由 `JOBPROOF_NOTIFICATION_EMAIL_PROVIDER=smtp` 打开。用户还可以在自己的“设置 › 通知”里关掉某一类邮件。
- 发送邮件验证码仍需 `JOBPROOF_VERIFICATION_EMAIL_PROVIDER=qq-smtp`（生产环境默认）；这个名字是历史沿用，实际支持任何 SMTP 服务器。
- **授权码只写不读**：用部署的主密钥（`JOBPROOF_AI_MASTER_KEY`，与 AI 通道密钥相同）以 AES-GCM 加密保存，接口不返回、页面只显示“已保存”，留空保存表示不修改。没有主密钥时不能在后台保存授权码，页面会说明。
- **校验**：服务器地址、端口（1–65535）、加密方式（SSL / STARTTLS / 不加密）、发件地址格式；QQ 邮箱与腾讯企业邮要求发件地址与登录账号一致，保存前就拦下。两位管理员同时修改时，后保存的一方会被提示刷新（版本号）。
- **测试**：每 10 秒最多一次，连接与读写超时 10 秒，不会把请求卡住。
- **审计**：保存、恢复、测试都写入审计日志（`MAIL_SETTINGS_UPDATED` / `CLEARED` / `TESTED`），只记录服务器、端口和打码后的账号。
- 邮件里的“查看详情”链接默认使用站点地址 `JOBPROOF_PUBLIC_ORIGIN`；公网地址不同时再设置 `JOBPROOF_PUBLIC_BASE_URL`。

## 4. 接口

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/api/v1/admin/mail-settings` | 当前状态、后台配置（不含授权码）、环境变量摘要、最近一次测试、发送情况 |
| PUT | `/api/v1/admin/mail-settings` | 保存；`password` 留空表示不修改；`expectedVersion` 防止覆盖他人的修改 |
| DELETE | `/api/v1/admin/mail-settings` | 恢复为环境变量 |
| POST | `/api/v1/admin/mail-settings/test` | `{ to }`，返回 `{ ok, message, at }` |

均只允许管理员。

## 5. 实现

- `shared.mail.MailTransport`：“当前用哪个账号发信”。邮件模块的 `MailSettingsService` 实现它：读取后台配置并按版本缓存 `JavaMailSender`，没有时退回 Spring 根据环境变量创建的发信器。
- 验证码发送（identity 模块）与提醒邮件发送（notification 模块）都只依赖这个接口，不直接读取环境变量。
- 表 `mail_settings`（单行 `default`），见 V77。

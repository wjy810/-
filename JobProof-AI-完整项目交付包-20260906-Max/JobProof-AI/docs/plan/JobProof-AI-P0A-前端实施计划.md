## 1. 背景与门禁

### 1.1 背景

P0A 要把求职者从「登录 → 画像与证据 → 粘贴 JD 并单岗位匹配 → 冻结简历并投递 → 记录面试轮次与基础复盘」走通，登录后落在求职工作台。工作台只锁定**读取边界**，不冻结卡片、排序或快捷操作。

当前阶段：第一至第四轮及冻结前补包已确认，P0A 已于 2026-08-18 冻结。本文是「对应后端切片可交接之后」才准执行的前端实施计划，不是准予立刻出码、也不是准予铺正式 Mock 工程的开工令。

### 1.2 两道门禁（缺一不可）

| 门 | 条件 | 未过门时 |
| --- | --- | --- |
| 门一：契约冻结 | 已于 2026-08-18 亲口冻结（放权旨） | 门已过。仍不得把正式 Mock 优先写成默认路径；第 5、6 轮及 P0B/P1/P2 不得提前实现 |
| 门二：该切片后端可交接 | 该切片已有可消费的版本化应用契约、错误语义、任务/对象版本与冲突语义，以及可演示的真实数据闭环 | **只准等，不准提前做该切片页面。** 不得用页面字段反推接口，不得用本地假数据顶替未交接契约 |

执行总则：

1. 门一已过。门二未过则该切片前端按兵不动。
2. 已冻结，仍按 S0 → S5 **一次只做一个切片闭环**。
3. 某切片后端未可交接，该切片页面不得开工；已交接切片不得顺手把下一切片页面做完。
4. 前端只消费已确认业务操作。发现未确认字段、状态、权限、异常或模块影响，记缺口并退回 P3.5，不得在页面里默认补规则。
5. 服务端事实是最终来源。前端不得用本地状态覆盖正式状态，不得靠藏按钮代替服务端鉴权。

### 1.3 过门后的主路径（不是 Mock 优先）

```text
陛下已于 2026-08-18 冻结
  -> 户部/后端交出 Sx 契约与可验证数据
  -> 工部只做 Sx 页面，且只挂已确认操作
  -> 该切片联调闭环可演示
  -> 再等 S(x+1) 后端可交接
```

允许：冻结后按切片消费后端已交付的契约与数据，页面只承载已确认操作。

不允许：把「先做完整正式 Mock，再接后端」写成默认主路径；不允许现在就安排探索稿编码。

## 2. 不做事项

本计划执行期内明确不做：

| 类别 | 不做 |
| --- | --- |
| 正式 Mock 优先 | 不写正式 Mock 数据文件、不把 Mock 当成默认开发主路径、不把确认记录里的 `MOCK-*` 编号理解成「现在去造假数据」 |
| 探索稿出码 | 不安排现在做探索稿 / 低保真页面编码；不得用探索稿反推字段、API、状态 |
| 未到时机的出码 | 该切片后端未可交接时，不写页面、组件、交互稿，不走 elite-web-designer 出码 |
| P0B 页面 | 收藏、多岗位推荐、漏斗摘要、面试准备包 / 模拟面试、基础风险报告、完整通知中心、邮件短信日历、完整偏好中心、个人统计、运营 / 合规可视化后台 |
| P1 / P2 页面 | 企业核验与付费查询、薪资谈判、Offer / 合同审核、实时 Copilot、录音转写、自动发送、自动代聊、平台自动操作 |
| 未确认按钮 | 确认记录「禁止默认增加」列中的入口一律不准做；映射表没有的按钮、表单、弹窗、批量操作不准默认生成 |
| 工作台越权 | 不冻结工作台卡片布局、排序或快捷操作；工作台不拥有业务状态，不在首页发明写入 |
| 登录越权 | 不做手机号登录、第三方登录、MFA |
| 技术越权 | 不用 React 作 P0A 主路线；不用 Python 跑项目；不在前端拼多个底层请求冒充服务端事务 |
| 他档越权 | 不写后端实施计划、不设计库表、不定义正式 API 字段、不改业务契约正文 |

P0A **页面范围只准这些工作区**：登录、画像、证据、JD / 匹配、简历、投递、面试轮次、基础复盘、最小通知、数据导出 / 删除、工作台。多一块都不准。

### 3.3 确认记录未单列的两个工作区（禁止补按钮）

**JD / 匹配**：第 10.2、13.2 未单列工作区。页面只准承载第 4 节已确认的用户意图，不得另发明入口。已确认意图摘录如下，不是新按钮清单：

- 粘贴 JD 文本；AI 解析只是候选；用户确认后才成为正式岗位事实。
- 正式匹配前至少确认：岗位名称、主要职责、硬性技能、经验要求、学历要求、地点、工作方式。未提供的薪资、福利等保持未知。
- 查看可解释匹配报告：总分、分项、加分项、扣分项、缺失项、对应证据、AI / 规则依据、置信信息、未知项。
- 输入变化后，旧报告由 `CURRENT` 转为 `STALE`；是否重算由用户发起，不得自动重算。
- `PENDING` / `RUNNING` 可取消；手动重试规则见第 4.5 节。`STALE` 默认可查看、可与新 `CURRENT` 对比，用户可主动归档。
- 重复 JD：全文相同则复用；公司与岗位名相同但正文有变时由用户选择并入或新建。除全文相同外不得自动合并。
- **禁止默认增加**：收藏、自动创建投递、自动改简历、报告物理删除、用未知当缺口、用薪资 / 风险 / 回复率 / 敏感属性计分、空限制白送分。

**求职工作台**（PRD 8.3、架构 6.3.1）：只锁定读取边界，**不冻结卡片、排序、快捷操作**。工作台只负责展示、导航和继续任务，不拥有业务状态；写入必须走对应领域已确认操作。

只准读取：求职画像完成度、能力证据完成度、最近导入的 JD、当前单岗位匹配结果、当前简历版本、当前投递进度、即将进行的面试、待完成的面试复盘、AI / 异步任务状态、当前待办任务。

工作台入口必须能回溯到上表已确认操作。P0A 首页不得出现：漏斗摘要、风险提醒、多岗位推荐、收藏、企业付费查询、薪资谈判、合同审核、实时语音、自动发送、自动跳过。公开宣传首页不纳入 P0A 核心验收。

## 4. 切片接入顺序与后端对齐

顺序抄架构 0.2 / 19.2，**一次一个闭环**。执行顺序改按第 1.3 节：先冻结，再等该切片后端可交接，再做该切片页面。

```text
S0 基础底座
  -> S1 用户画像与能力证据
  -> S2 JD 文本导入与单岗位匹配
  -> S3 简历版本与投递
  -> S4 面试记录与基础复盘
  -> S5 登录后的求职工作台
```

### 4.1 各切片前端只做什么、等后端交什么

| 切片 | 后端主要模块（依赖，本计划不写后端文件） | 前端只开的工作区 | 该切片闭环看起来像什么 |
| --- | --- | --- | --- |
| S0 | Identity、Data Rights、Task、Notification、Audit | App Shell（路由、登录态、全局错误边界）、登录、最小通知、数据权利 | 邮箱注册 / 登录 / 验证码重置 / 退出；改密后旧会话失效；站内通知查看与已读；导出与删除申请能看到进度，不得提前显示全部完成 |
| S1 | Profile、Evidence | 画像、证据库 | 无求职方向不得匹配；候选须确认 / 拒绝；六类证据可创建 / 归档 / 复制；已引用正文不可改 |
| S2 | Job、Matching | JD / 匹配（按第 4 节，不发明入口） | 粘贴文本、确认岗位事实、可解释报告、任务取消 / 重试、`STALE` 可看可对比可归档；不得自动建投递 |
| S3 | Resume、Application CRM | 简历中心、简历编辑器、投递看板 / 详情 | 未确认不得可投递 / 冻结；投递必须绑冻结版本和 `CONFIRMED` 岗位；非法流转禁用并说明原因 |
| S4 | Interview、Review | 投递详情 / 轮次、基础复盘 | 不强制建轮次；轮次结果不改投递；未确认不写弱项；完成复盘时未处理项不写入 |
| S5 | Web Workspace 查询、Task UI Adapter | 求职工作台 | 只汇总第 3.3 节读取对象；入口均可回溯已确认操作；不冻结卡片布局 |

S0 登录成功后，只进入已交付切片的最小落地（账号 / 数据权利或已开门的工作区）。**不得在 S5 之前把工作台卡片方案做死。**

### 4.2 对后端只提依赖，不代替后端计划

每个切片开工前，工部只核验户部是否交出下列可消费物（缺则停，不自行补接口）：

1. 版本化应用契约（命令 / 查询 / 异步任务语义分开），不是页面字段清单。
2. 错误语义：用户可修正、权限禁止、状态冲突、依赖失败、系统故障。
3. 写命令的对象版本与冲突拒绝（拒绝覆盖，保留双方内容让用户选——以确认记录为准）。
4. 长任务：任务 ID、可查询状态、失败原因、是否允许取消 / 重试以该任务契约为准。
5. 对象级授权结果由服务端判定；前端只表现，不裁定。

前端分层只守架构 6.3，本阶段不落文件：App Shell、Feature、Server State、Form State、Local Preference、Upload Client、Task UI Adapter。Feature 按 Profile、Evidence、Job、Matching、Resume、CRM、Interview、Review 等组织；只能调本 feature 的应用契约或公共查询。

建议目录（过门后再建，现在不建）：

```txt
src/features/<workspace>/
  pages/
  components/
  services/
  types/
  hooks/
  utils/
  index.ts
```

### 4.3 切片完成证据（前端侧）

某切片可进入下一片之前，至少同时满足：

1. 该切片映射表中的已确认操作都能在真实数据上走通。
2. 「禁止默认增加」列没有任何入口。
3. 第 6 节状态清单对该切片已确认操作可演示。
4. 未把下一切片的页面或未确认按钮捎上。

P0A 前端总出口：S0–S5 均按上表闭环，且工作台只读汇总、入口可追溯。此出口仍不等于可以说「全部完成」——须有联调证据。

## 5. 多智能体分工

### 5.1 拆法

按**工作区 / feature 目录**拆人，不按「顺手把相邻页也改了」拆。主官负责拆分、边界、合并、冲突检查和验收。

| 角色 | 可改范围 | 禁止 |
| --- | --- | --- |
| 主官（工部计划 / 调度） | 本计划、跨 feature 路由与 App Shell 的合并、缺口退回 P3.5 | 未过门就派出发码；默许同文件并行 |
| 身份 / 数据权利官 | `features/identity`、`features/data-rights` | 改通知文案规则、改工作台布局 |
| 通知官 | `features/notification` | 做邮件短信、偏好中心、关闭安全通知 |
| 画像官 | `features/profile` | 把未知写成事实、采集敏感属性 |
| 证据官 | `features/evidence` | 允许改已引用正文、无引用检查就硬删 |
| 岗位匹配官 | `features/job`、`features/matching` | 收藏、推荐、风险、自动投递 |
| 简历官 | `features/resume` | 未确认标可投递、覆盖已绑定版本 |
| 投递官 | `features/application` | 收藏、漏斗、批量改状态、自动改状态 |
| 面试官 | `features/interview` | 强制建轮次、录音、回写投递 |
| 复盘官 | `features/review` | 未确认写弱项、训练任务、准备包 |
| 工作台官 | `features/workspace` | 冻结卡片方案、拥有业务写入、露出 P0B / P1 入口 |
| 视觉出码（elite-web-designer） | 当前切片、当前工作区的页面方案与实现 | 该切片后端未交接或契约未齐时出码；跨工作区同时改同一文件 |

### 5.2 同文件禁令

- **禁止**两名或以上代理同时改同一文件、同一路由总表、同一 App Shell、同一公共类型或同一设计令牌文件。
- 跨工作区共享物（路由、守卫、全局错误、契约生成类型）只准主官串行合并，或加锁后一人改完再换下一人。
- 调研、读文档、验收可以并行；写页面必须文件范围隔离。
- 发现并行碰同一文件：停写、主官收 diff、以先锁或主官裁定为准，不得各写各的硬合。

### 5.3 何时才走 elite-web-designer

elite-web-designer 只处理页面方案、视觉与交互，**不设计业务规则**。本计划**现在不启动它**。

准召时机（同时满足）：

1. P0A 已于 2026-08-18 冻结。

## 6. 状态覆盖（验收清单，不是现在做 Mock）

以下各态是**每个已开门切片、每个已确认操作**的验收清单。不据此制作正式 Mock 工程，也不据此在后端未交接时开工页面。

| 态 | 工部要能演示什么 | 对照提醒（抄确认记录，不新增规则） |
| --- | --- | --- |
| 正常 | 已确认操作成功，状态与服务端一致 | 例如登录成功、确认画像、冻结版本、合法前进投递 |
| 加载 | 查询与长任务进行中不可误点成第二次提交 | 解析 / 匹配 / 复盘 / 导出删除为异步任务时看任务态，不解释供应商内部态 |
| 空 | 无数据时给引导，不假装有事实 | 无求职方向、无证据、无冻结版本、无轮次（允许 0 轮）都是合法空，不得默认补事实 |
| 错误 | 失败原因可理解，保留可重试路径（仅当契约允许） | 非 JD、超长超短、复盘分析失败、导出过期链接作废 |
| 权限 | 非本人或越权看到禁止态，而不是半套表单 | 被分享人只读；导师默认不进 P0A；运营默认不看原文 |
| 校验 | 表单未过校验不得当成功 | JD 80–20000 字；匹配前必有求职方向与七项确认；关键成果无证据须逐条确认才能冻结 |
| 提交中 | 提交中按钮禁用，防重复提交 | 写命令带幂等与版本 |
| 禁用 | 当前态不允许的操作可见但不可用，并说明原因 | 未确认不得可投递 / 冻结；非法流转；已绑定版本不可原地改；已引用证据不可改正文 |
| 冲突 | 并发拒绝覆盖，保留双方内容让用户选 | 投递、轮次等确认记录写明的乐观并发 |

危险操作（改密导致全会话失效、接受后撤回、对象 / 账号删除）必须二次确认，并展示关联影响与不可逆说明。通知失败、匹配失败、`无法判断` 都不得回滚或改写无关业务状态。

确认记录中的 `MOCK-*` 编号（如 `MOCK-RESUME-002`、`MOCK-CRM-003`、`MOCK-AUTH-001`）在过门后当作**验收场景名**，用来对已确认异常，不是去落正式 Mock 数据工程。

列表若该切片契约包含分页 / 筛选 / 排序，过门后一并验收；契约没有的筛选条件不准页面先发明。

## 7. 风险与回滚

| 风险 | 为何危险 | 回滚 / 处置 |
| --- | --- | --- |
| 门一已过但后端未交接就出码 | 用页面反推接口，重蹈 Mock 优先 | 停该切片前端；等户部交接；已写页面不得倒逼改契约 |
| 发明未确认按钮 / 字段 / 状态 | 破坏冻结纪律 | 去掉入口；缺口退回 P3.5，不在前端补规则 |
| 把架构旧句「先 Mock 再后端」当令 | 违反全局规则 v3.0 与本圣旨 | 以本计划第 1.3 节为准；架构 19.2 已改为后端先行 |
| 工作台先锁卡片布局 | 把读取边界误当成 UI 冻结 | 去掉布局假设；工作台只保留读取与可追溯导航 |
| 同文件并行改 | 合并不可回放、契约被悄悄改 | 丢弃后到者或由主官重放；加文件锁 |
| 把 P0B / P1 入口做进 P0A | 范围膨胀 | 删除入口、菜单、路由；不留隐藏彩蛋 |
| 前端本地态覆盖正式态 | 用户看见假成功 / 假阶段 | 回退该 Server State 用法；以服务端为准 |
| 用 Python 跑前端 | 违反选型与全局规则 | 停用该脚本；回到 Node + Vite |
| 冻结后陛下改规则 | 旧页面违契 | 先改确认记录与映射表，再评估该切片页面；宁可回退切片，不硬改 |

大改前单独分支。优先回滚而不是硬修的情况：新页面破坏已闭环切片、大面积发明操作、契约与实现对不上、偏离本计划。
